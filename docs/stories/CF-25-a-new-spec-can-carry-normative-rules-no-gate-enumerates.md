# A new spec can carry normative rules no gate ever enumerates

## Goal

Make an unregistered normative spec impossible to ship silently: every file under `docs/specs/` is
either registered in the checker's spec set or explicitly and visibly excluded, so a spec's rules
cannot exist outside the coverage picture that claims to describe them.

## Acceptance

- [x] `scripts/check-vectors.py` enumerates `docs/specs/*.md` against its own `SPECS` table
      (`scripts/check-vectors.py:92-118`) and fails on any spec that is registered nowhere. An
      exclusion is a named entry with a reason, not an absence.
- [x] `EX-12`'s unowned-row guard fires on rule tables whose first cell is not shaped `XX-N`.
      `ANY_ROW_LINE` (`scripts/check-vectors.py:131`) matches only that shape today, so a table
      keyed by, for example, a backticked test-function name is invisible to it.
- [x] **Failing-first:** on a tree containing `docs/specs/owner-rpc.md` with no `SPECS` entry, the
      check is red and names the file. Demonstrated red before the fix, green after — and green only
      because the spec is registered or explicitly excluded, not because the rule was relaxed.
- [x] The published conformance count and inventory move with it: a spec that is registered but
      contributes no rows must not read as covered. Coordinate with `CF-21`, which owns holding a
      published count to its generator.
- [x] `scripts/gate.sh` is green.

## Progress
- 2026-08-05 — Implemented in `scripts/check-vectors.py`, on `impl/CF-25`.
  - **Enumeration** (`unenumerated_specs`, `:478`): every file under `docs/specs/` must be
    registered in `SPECS` or named in the new `EXCLUDED` registry (`:171`) with a reason. Both
    directions ratchet: a spec in neither place, an entry whose document is gone, whose spec is
    also registered, whose reason is empty, or whose `story` is closed/nonexistent are each
    refused — `CF-24`'s liveness rule applied to this ledger (an empty `story` is legal and means
    the claims are carried by a registered prefix's own rows, `cluster-membership` §11's shape).
  - **Widened row guard** (`SCENARIO_LINE`, `:224`; `unowned_rows`, `:403`): a rule-table row
    keyed by a backticked snake_case test-function name (three-plus words — two-word schema
    fields like `call_id` stay invisible on purpose) is a named executable claim, admitted only
    in a document `EXCLUDED` names. This also surfaced `docs/designs/extension-framework.md`'s
    eleven `external_route_*` scenarios, now entered with `EX-3` as executor (EX-6's own handoff
    names it); `owner-rpc.md` entered with `AF-7`.
  - **Registration cannot be nominal** (`rowless_registrations`, `:536`): a `SPECS` prefix whose
    owner tabulates no row of it is refused, so excusing a spec from the enumeration by
    registering an empty prefix does not read as coverage. This is the generator-side half of
    `CF-21`'s principle; the report now states the document counts (13 registered / 15 prefixes /
    2 excluded specs) and carries an *Outside the vector ledger* section, both computed from the
    registries, for `CF-21` to hold published copies against.
  - **Failing-first**, demonstrated with the registry empty against the base tree
    (`134e7e1`): 28 problems, exit 1, among them `docs/specs/owner-rpc.md: a spec registered
    nowhere …` plus per-line hits on all thirteen §10 scenarios. Green after the entries were
    added; no rule relaxed. The case is also replayed by `--self-test` on every invocation
    (`:1255`), synthetic tree, so the demonstration cannot rot.
  - `docs/reference/conformance.md` regenerated by the script.

## Notes

- **Found by the independent review of `AF-3`'s diff, 2026-07-31**, while answering the question
  "can the gate be green with thirteen named, unexecuted scenarios and no registered rows?" The
  answer was yes. `docs/specs/owner-rpc.md` is 296 normative lines with a §10 scenario table, and
  `check-vectors.py --check` passed at **154/583 proved, 19 shape-only, 410 deferred, exit 0** with
  none of it in view. `SPECS` has no `owner-rpc` entry, and `EX-12`'s guard could not fire because
  §10's first cell is a backticked function name rather than `XX-N`.
- **This is a gate hole, not `AF-3`'s defect.** `AF-3` had a sound reason not to register rows — a row
  and the test that executes it should arrive in the same commit, which is `cluster-membership` §11's
  own reasoning and what `CF-8`/`EX-12` paid for. The hole is that *choosing* not to register leaves
  no trace anywhere a tool looks. §11 got this right by mapping onto an already-registered prefix
  whose rows all sit in `vector-scope.toml` with a reason and a story, so `CF-16`'s sweep finds them.
- **Same family as `CF-19`, `CF-21`, `CF-23` and `CF-24`** — a document making a claim no tool
  compares against anything. `CF-24`'s note says whoever lands the last of them should state the
  general rule once in `AGENTS.md`; this story is now part of that set, and it touches the same file
  as `CF-24` (`scripts/check-vectors.py`), so the two should not run concurrently.
- Considered for upstream: **no.** This checks this repository's own spec set and coverage ledger.
