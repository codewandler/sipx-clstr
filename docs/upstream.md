# Upstream dependency ledger — what sipx-clstr needs from sipx

sipx-clstr builds on the [sipx](https://github.com/codewandler/sipx) kernel and, per the working agreement
([AGENTS.md](https://github.com/codewandler/sipx-clstr/blob/main/AGENTS.md) → *Upstream first*), never shadow-implements protocol logic that
belongs there. This ledger tracks every kernel gap this platform depends on: what it is, which
sipx story covers it (`CX-1` filed the first of them; a row opened since carries its own filer, or
says `— (not yet filed)` until it has one), and which sipx-clstr stories it blocks. Two repos sharing
a boundary is this project's biggest coordination risk; this table keeps it auditable.

**State of play — sipx `v0.4.0` cleared this ledger, and it has not stayed clear.** Every row filed
by `CX-1` landed in one release: `S-15`, `S-16`, `T-14`, `T-16`, `T-17`, `T-18`, `T-19` and `X-20`
are in the tag this workspace pins. Of those, the only one that is not `landed` is `X-15`, which was
filed as an offer and which `CF-1` had already decided stays local. **Four rows opened after that
release; `CX-4`'s bump to `v0.10.0` closed one of them and left three:** the `TimerQueue` `Default`
bound that pinned the MSRV floor (`CF-9`) is **fixed in `v0.10.0`**, while the nonce that carries no
per-challenge entropy (`CX-5`), the replay window that scans its whole capacity on every
authenticated request (`RG-15`), and the overload path that logs per message on the loop that must
keep timers running (`DP-11`) are open and unfiled. The independent review added two capability
gaps: a public proxy-usable outgoing-CANCEL operation (`PX-12`) and exact cleartext listener
selection (`FC-1`). All five were found by reading the kernel — and, for the replay window, by
measuring it — rather than by a release note, which is the only way rows like these surface.

**Five more rows came from the other direction — writing specs against the kernel (`CX-6`).** The
four above were found by reading released kernel code, which is how a *defect* surfaces. These five
are capability gaps, found while writing `docs/specs/`: the kernel does exactly what it says, and a
spec needs something it does not say. A public RFC 3966 split of a `tel:` URI, a way to replace a
URI's user part, a typed `P-Asserted-Identity`/`P-Preferred-Identity` value list, a parsed `Privacy`
header — four decided **upstream** and unfiled — and the RFC 5393 loop-detection branch cookie,
**declined**, which stays here with its local plan recorded. Same table, different provenance, and
the rows read differently for it: a defect row carries a reproduction, a capability row carries the
kernel's current surface and what is missing from it.

**They are late, and the cause of the lateness is worth more than the rows.**
`asserted-identity` §2, `number-normalisation` §1 and `proxy-behavior` §1 each named `CX-1` as the
story that would file its gap here. `CX-1` was `done` before any of the three was written, so the
promise was made on a closed story's behalf by documents it never read — which is exactly why
nothing noticed until `CF-16` swept for that shape. Nothing about `CX-1` failed: its scope was that
every **open ledger row** have a sipx story, and it discharged that. A spec that defers upstream work
therefore names **this document**, never a story, and `scripts/check-docs.py` now holds every
paragraph in `docs/specs/` to it.

**The row that closed was never filed upstream, and closed anyway.** `v0.10.0` bounds the impl
(`impl<K: Eq, I: Ord> Default for TimerQueue<K, I>`, `sipx-transport/src/timers.rs:66`) with a
comment naming the same `BinaryHeap::new` bound this ledger did. That is worth recording for what it
implies rather than as good news: an unfiled row can be closed by someone else solving their own
version of the problem, so the ledger has to be re-read against the kernel even for rows nobody is
waiting on. It is also the whole of the MSRV consequence — the floor this workspace declares came
*down* from 1.94 to 1.91, and what holds it at 1.91 is now local code rather than the kernel.

The two that remain are both in `sipx-ua/src/challenge.rs` and they are **different defects**:
`CX-5` is about what the nonce *is*, `RG-15` about what the window *does* with it. Neither is fixed
by moving the pin, and this is now checked rather than assumed: `challenge.rs` is byte-identical at
`v0.7.0`, `v0.8.0`, `v0.9.0`, `v0.10.0` and kernel `main` — one blob, `30e1d290`, at all five refs —
so `CX-4` closed neither and no bump short of a new release will.

One row reopened on contact with the code and closed again the same day: `X-14` generalized
`TimerQueue` over its key rather than its clock, so the harness could not drive it from virtual
time; **`v0.7.0` makes the instant generic too** and the row is `landed`. The workspace pins
`v0.10.0`. This is the third time a row here was believed rather than read — the TLS row stayed
`open` through the release that closed it, and this one read `landed` for a day before anyone
tried to use it. Re-read the kernel before trusting a row.

**Every row below was re-read against `v0.10.0` by `CX-4`**, not carried forward: each cited symbol
was opened in the kernel at that tag. Two rows changed as a result — the `TimerQueue` `Default` row
to `landed`, and the `Path`/`Service-Route` row's line numbers, which **were wrong when they were
filed** rather than having drifted since. `address.rs` is one blob (`14817570`) at `v0.4.0`, `v0.7.0`
and `v0.10.0`, so nothing about that file moved between the release that closed the row and the tag
this workspace pins; the citation was mis-taken at the time, reading `Path`'s doc-comment line and
`Path`'s match arm as though they were the two headers' arms. This distinction is not pedantry, and
it is the reason to state it: "drifted" says the kernel moved and the ledger fell behind, "wrong when
filed" says a row was written from something other than the code. Only the second is a claim this
ledger's own rule — re-read before trusting a row — exists to catch, and a correction that invents a
drift to explain itself is the failure mode dressed as the fix.

**Re-read and not filed:** validated finding V-13 does not expose a kernel gap. The pinned
`v0.10.0` already has the fallible typed `sipx_sip::headers::Expires` surface, which distinguishes a
malformed-present header from an absent one. `RG-20` must consume that result and reject malformed
Contact parameters and Path values atomically. No generic primitive is missing, so filing a kernel
story would move a consumer defect across the boundary rather than fix it.

**Decided (not upstream):** the proxy transaction driver — one server transaction fanning out to
N client transactions — is built **here**, directly over `sipx-sip`'s sans-IO `TransactionLayer`.
The sipx transport driver stays UA-shaped; only generic primitives move upstream. The RFC 5393
loop-detection branch cookie joins that decision as of `CX-6` (row below): it is keyed with the
cluster's own key family and its inputs are this driver's routing state, so it moves only if the
kernel ever grows a proxy.

| A replay window that is `O(1)` on the hot path | `challenge::Authenticator`'s window is `seen: VecDeque<(String, u32, String)>` (`sipx-ua/src/challenge.rs:194` at `v0.10.0`, and unchanged since `v0.7.0`), and `record` finds an entry with `self.seen.iter_mut().find(…)` — a front-to-back scan (`challenge.rs:388,391`). The nonce being checked is always the **newest**, because `record` appends with `push_back` (`challenge.rs:411`), so the scan finds it last: every authenticated request walks the whole window. `REPLAY_CAPACITY` is 4096 (`challenge.rs:29`). **Measured**, on the pinned tag, timing `verify_at` alone with the client's answers precomputed: **7.5 µs** per verify against a one-entry window and **19.2 µs** against a full one — ~11.6 µs of pure scan per authenticated REGISTER, 2.5× the whole cost of verifying. In this platform that runs under the node-wide authenticator lock (`sipx-clstr-node/src/driver.rs:765`), so it is a ceiling on the node rather than on one request. A map keyed by nonce makes it a lookup, and eviction needs an insertion order alongside it — the bound in `§6`'s third bullet must survive the change, since an unbounded window is the memory leak an attacker sizes by asking for challenges. **Reproduction, in the kernel alone:** one `Authenticator`, 4096 distinct nonces each authenticated once, then time `verify_at` on the newest against the same call on a fresh authenticator. Rules of the ledger:

- A row is **open** until the sipx story is filed, **filed** once it exists (link it), **implemented
  upstream, unreleased** once the kernel code exists but no tag this workspace can pin carries it,
  and **landed** once released in a sipx version this workspace can pin.
- *Unreleased* is a real state and not a formality. Code on someone's `main` is not a dependency:
  `Cargo.toml` pins a **tag** from the GitHub URL precisely so "which kernel is this claim true of?"
  has an answer, and a story that consumes unreleased kernel code is still blocked. The remedy is a
  release, not a `[patch]` — patching to a local checkout makes the build unreproducible and hides
  the dependency from exactly the ledger that exists to track it.
- Blocked sipx-clstr stories carry the marker in their `note:` field and name this file.
- **A spec defers to this document, never to a story.** A story is a dated object that closes; this
  file is not, which is the whole reason it exists. Three specs named `CX-1` as the story that would
  file their gap, `CX-1` closed before the first of them was written, and the three gaps sat in
  prose for as long as it took someone to sweep for the pattern (`CF-16` → `CX-6`).
  `scripts/check-docs.py` enforces the two mechanical halves: a paragraph under `docs/specs/` that
  says *ledger row* must link this file, and no such paragraph may name a story as the thing that
  will file or raise the row.
- If a gap turns out to be clstr-specific after all, the row records that decision instead of
  silently disappearing.
- A row can also be wrong. The TLS/WS/WSS row above was written against sipx 0.1.0 and stayed
  `open` through a release that closed it; re-read the kernel before believing a row, and correct
  it when it lies.
