# Upstream dependency ledger — what sipx-clstr needs from sipx

sipx-clstr builds on the [sipx](https://github.com/codewandler/sipx) kernel and, per the working agreement
([AGENTS.md](https://github.com/codewandler/sipx-clstr/blob/main/AGENTS.md) → *Upstream first*), never shadow-implements protocol logic that
belongs there. This ledger tracks every kernel gap this platform depends on: what it is, which
sipx story covers it (filed by `CX-1`), and which sipx-clstr stories it blocks. Two repos sharing
a boundary is this project's biggest coordination risk; this table keeps it auditable.

**State of play — sipx `v0.4.0` cleared this ledger, and it has not stayed clear.** Every row filed
by `CX-1` landed in one release: `S-15`, `S-16`, `T-14`, `T-16`, `T-17`, `T-18`, `T-19` and `X-20`
are in the tag this workspace pins. Of those, the only one that is not `landed` is `X-15`, which was
filed as an offer and which `CF-1` had already decided stays local. **Three rows have opened since,
and none is filed upstream yet:** the `TimerQueue` `Default` bound that pins the MSRV floor
(`CF-9`), the nonce that carries no per-challenge entropy (`CX-5`), and the replay window that scans
its whole capacity on every authenticated request (`RG-15`). All three were found by reading the
kernel — and, for the last one, by measuring it — rather than by a release note, which is the only
way rows like these surface.

Two of the three are in `sipx-ua/src/challenge.rs` and they are **different defects**: `CX-5` is
about what the nonce *is*, `RG-15` about what the window *does* with it. Neither is fixed by moving
the pin — `challenge.rs` is byte-identical between `v0.7.0`, `v0.10.0` and kernel `main` — so
`CX-4` will close neither.

One row reopened on contact with the code and closed again the same day: `X-14` generalized
`TimerQueue` over its key rather than its clock, so the harness could not drive it from virtual
time; **`v0.7.0` makes the instant generic too** and the row is `landed`. The workspace pins
`v0.7.0`. This is the third time a row here was believed rather than read — the TLS row stayed
`open` through the release that closed it, and this one read `landed` for a day before anyone
tried to use it. Re-read the kernel before trusting a row.

**Decided (not upstream):** the proxy transaction driver — one server transaction fanning out to
N client transactions — is built **here**, directly over `sipx-sip`'s sans-IO `TransactionLayer`.
The sipx transport driver stays UA-shaped; only generic primitives move upstream.

| A nonce with per-challenge entropy | `challenge::Authenticator::mint` builds `<issued-at in hex>.<HMAC-SHA-256(issued-at ":" realm)>` (`sipx-ua/src/challenge.rs:287,294` at `v0.7.0`) — a pure function of the second, the realm and the secret, with nothing per-challenge in it. So two clients challenged in the same second are handed the byte-identical nonce, and the replay window is keyed on the nonce string with one nonce-count per nonce (`seen`, `challenge.rs:194,388`): the first to authenticate at `nc=1` takes the count, and the second — different user, correct password, also at `nc=1` — is `Reason::Replay`. Nonce minting is an auth primitive, so kernel surface by [AGENTS.md](https://github.com/codewandler/sipx-clstr/blob/main/AGENTS.md) #6, and `registrar-auth` §7.3 already records that this repository may not touch it | — (not yet filed) | `CX-5` (`registrar-auth` §6.1 `N1`, and its `RA-R-8`); every tenant that declares `auth` since `FC-3` made it real | **open** — found by `CX-5` reading the mint rather than by a release note. Not fixed by `CX-4` either: `challenge.rs` is byte-identical between `v0.7.0` and `v0.10.0`, so the bump moves the pin without moving this |
| Async / shared-cache resolver option | `Resolver` trait is sync with per-URI prefetch; fine for a UA, insufficient at proxy throughput; `_sip._ws`/`_sips._wss` SRV prefixes not prefetched | [T-17](https://github.com/codewandler/sipx/blob/main/docs/stories/T-17-resolution-at-proxy-throughput.md) | RT-1 | **landed in 0.4.0, decision recorded** — settled *upstream* by `RT-1`: `dns::resolve_uri` (async), `DnsResolver` (shared cache, TTLs both ways, `Answer::Unavailable` uncached), all five SRV prefixes prefetched. No caching layer is built here; `RoutePlan` wraps the kernel's `Target` |
| Deterministic timer queue + seeded loopback link (`sipx-testkit`) | `sipx-transport`'s `TimerQueue` reads `Instant::now()` inside `set` and is keyed to `(TransactionKey, Timer)`; the testkit's crate doc promises a loopback transport and ships none — its modules are `certs`, `load`, `rfc4475`, `soak`. | Timer queue drivable from a virtual clock | `X-14` generalized `TimerQueue` over its **key** and passes `now` in, but the instant type is still `tokio::time::Instant` (`timers.rs:19`), whose only constructors are `now()` and `from_std` — a virtual clock cannot build an epoch. `TimerQueue` also stores keys without payloads, where the harness needs deliveries, timers and breaks in one totally ordered queue. `testkit::Link` is two-party, has no stream class, and draws faults from its own generator rather than the harness's | — (closed by the kernel directly) | CF-7 | **landed in 0.7.0** — `TimerQueue<K, I = Instant>`, generic over its instant with the old type as the default, so `SimTime` can drive it. | A replay window that is `O(1)` on the hot path | `challenge::Authenticator`'s window is `seen: VecDeque<(String, u32, String)>` (`sipx-ua/src/challenge.rs:194` at `v0.7.0`), and `record` finds an entry with `self.seen.iter_mut().find(…)` — a front-to-back scan (`challenge.rs:388,391`). The nonce being checked is always the **newest**, because `record` appends with `push_back` (`challenge.rs:411`), so the scan finds it last: every authenticated request walks the whole window. `REPLAY_CAPACITY` is 4096 (`challenge.rs:29`). **Measured**, on the pinned tag, timing `verify_at` alone with the client's answers precomputed: **7.5 µs** per verify against a one-entry window and **19.2 µs** against a full one — ~11.6 µs of pure scan per authenticated REGISTER, 2.5× the whole cost of verifying. In this platform that runs under the node-wide authenticator lock (`sipx-clstr-node/src/driver.rs:765`), so it is a ceiling on the node rather than on one request. A map keyed by nonce makes it a lookup, and eviction needs an insertion order alongside it — the bound in `§6`'s third bullet must survive the change, since an unbounded window is the memory leak an attacker sizes by asking for challenges. **Reproduction, in the kernel alone:** one `Authenticator`, 4096 distinct nonces each authenticated once, then time `verify_at` on the newest against the same call on a fresh authenticator. The replay window is an auth primitive — `registrar-auth` §2's table names "the replay window's data structure" as explicitly *not* this platform's — so it is kernel surface by [AGENTS.md](https://github.com/codewandler/sipx-clstr/blob/main/AGENTS.md) #6 | — (not yet filed) | `RG-15`, whose acceptance asked for the fix and got this row instead; every tenant that declares `auth` since `FC-3` made it real | **open** — found by `RG-15` reading `record` and then measuring it, not by a release note. `CX-5` is filing a defect against the same file, and it is a different one: `CX-5` is about what the nonce *is*, this is about what the window *does* with it. Both want one release |
| `TimerQueue`'s `Default` impl forces the whole workspace to rustc 1.94 | `impl<K, I> Default for TimerQueue<K, I>` (`sipx-transport/src/timers.rs:63`) calls `BinaryHeap::new()` on a type parameter it does not bound. `BinaryHeap::<T>::new` carried a `T: Ord` bound that rustc only relaxed in **1.94**, so every consumer of `sipx-transport` inherits 1.94 as its floor — for a `Default` impl, not for anything the queue actually does. Bounding it (`K: Eq, I: Ord`) or writing `BinaryHeap { data: Vec::new() }`-equivalent would let both projects go back down | — (not yet filed) | `CF-9`; and any consumer with an MSRV policy | **open** — found by `CF-9` building the workspace on its own declared floor, which is the only thing that surfaces it: a developer on current stable never sees it |
| Released TLS/WS/WSS transports | Shipped in sipx **0.2.0** — TLS with a certificate policy (`T-6`, `T-7`), SIP over WebSocket (`T-8`), WSS (`T-9`), with interop runs against independent implementations (`T-10`). The `sipx-transport` features `tls`, `ws` and `wss` are on by default | — | M2 TLS edges (DP-2), M3 WSS clients | landed in 0.2.0 |

Rules of the ledger:

- A row is **open** until the sipx story is filed, **filed** once it exists (link it), **implemented
  upstream, unreleased** once the kernel code exists but no tag this workspace can pin carries it,
  and **landed** once released in a sipx version this workspace can pin.
- *Unreleased* is a real state and not a formality. Code on someone's `main` is not a dependency:
  `Cargo.toml` pins a **tag** from the GitHub URL precisely so "which kernel is this claim true of?"
  has an answer, and a story that consumes unreleased kernel code is still blocked. The remedy is a
  release, not a `[patch]` — patching to a local checkout makes the build unreproducible and hides
  the dependency from exactly the ledger that exists to track it.
- Blocked sipx-clstr stories carry the marker in their `note:` field and name this file.
- If a gap turns out to be clstr-specific after all, the row records that decision instead of
  silently disappearing.
- A row can also be wrong. The TLS/WS/WSS row above was written against sipx 0.1.0 and stayed
  `open` through a release that closed it; re-read the kernel before believing a row, and correct
  it when it lies.
